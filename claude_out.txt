How it's set up
- Video engine: your ESP32 code is unchanged — video on GPIO25, sound on GPIO32, LittleFS images, GIFs and the game. It lives in an external component at components/tvout/.
- Networking: ESPHome now does WiFi (same fixed IP, 192.168.1.81), OTA with a password, Home Assistant, and safe_mode. If a bad build makes the board boot-loop, safe mode still lets you flash over WiFi.
- Main loop: the old loop() now runs as its own task on core 1 (app.cpp). It holds the screen for seconds at a time, which ESPHome's main loop isn't allowed to do.
- Home Assistant entities: Mode (select), Message and Image (text), DVD trail (switch), sound buttons, and a Video field rate sensor that should read 60.00 Hz.
- MQTT: your old tvout/cmd|msg|img|snd|state topics still work, so existing automations don't need changes.
- Web page: the upload page and /game are unchanged, on port 80, and tools/push_logos.py works as before.
- TV during updates: an update shows "UPDATING..." on screen.
- Secrets: secrets.yaml holds the WiFi/MQTT values from your .ino, plus a newly generated API key and OTA password. Keep it private.

Things you need to know
- First flash must be over USB, and it erases LittleFS. OTA needs two app slots, so the partition table changed. Image space drops from about 1.9 MB to 1.19 MB (roughly 120 full-screen images). Any images you uploaded to the current board will be lost.
- Run ESPHome from PowerShell or cmd, not Git Bash. The ESP-IDF installer refuses to run under Git Bash.
- Builds go to C:/esphome-build/tvout-fgf. OneDrive locked the .esphome build folder inside the project and broke the build, so I set build_path in the YAML to a folder outside OneDrive.
- I removed captive_portal. It would want port 80, which the upload page uses. If WiFi fails, the fallback hotspot still accepts OTA at 192.168.4.1.
- All engine headers are wrapped in #ifdef TVOUT_ENGINE. ESPHome pulls every component header into its own main.cpp, and the engine's BLACK/WHITE macros would break ESPHome's code otherwise.

❯ can it be added to home assistant?

Yes, it's already set up for that. The YAML includes ESPHome's api: block, which is what Home Assistant connects to.

To add it after flashing:

1. Flash it first (USB the first time): esphome run tvout.yaml --device COM5.
2. Home Assistant will usually find it on its own. Look under Settings → Devices & services for a "Discovered: TvOut FGF" card and click Configure.
3. If it isn't found, click Add integration → ESPHome and enter host 192.168.1.81, port 6053.
4. When it asks for the encryption key, paste the api_key value from TvOut_FGF_ESPHome/secrets.yaml.

What shows up in Home Assistant:
- Mode: a dropdown with intro, show, message, dvd, butterfly, cube, game and birthday.
- Message and Image: text boxes. Typing in one changes the TV right away.
- DVD trail: an on/off switch.
- Buttons: Play birthday, Beep, Sound off and Restart.
- Diagnostics: Video field rate (should read about 60 Hz), WiFi signal, Uptime and IP address.

The Mode dropdown stays in sync with the TV, even when something else changes it (the web page, MQTT, or the boot intro ending).

Optional: manage it from Home Assistant's ESPHome add-on. This lets you do OTA updates with one click from Home Assistant instead of your PC:
1. Copy tvout.yaml, partitions.csv and the components/ folder into the add-on's /config/esphome/ folder.
2. Add the same keys to the add-on's secrets.yaml.
3. Delete the build_path: C:/esphome-build/... line, since that's a Windows path and the add-on runs on Linux.
4. The device then appears in the ESPHome dashboard, and Install → Wirelessly updates it over the air.

Example automation: this shows a message when the doorbell rings.
action: text.set_value
target:
  entity_id: text.tvout_fgf_message
data:
  value: "DOORBELL!"

About MQTT: the mqtt: block is only there so your old tvout/* topics keep working. Home Assistant doesn't need it. If you don't use those topics anymore, delete the block to save some flash.
